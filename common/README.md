# 공통 목업 도구

- 상단 사용구분의 마지막 선택값은 프로젝트별 브라우저 localStorage에 보관하여 새로고침·재방문 시 복원한다. 유효한 사용구분만 복원하고 첫 방문은 관리자로 시작한다. 명시적으로 목업 로그인·로그아웃을 실행하면 기존 관리자 전환 동작을 유지하고 저장된 선택값도 갱신한다. 실제 로그인 권한과는 별개인 목업 검토용 선택값이다.

## 기본 팝업 규칙 (2026-10-23)

- 페이지 안에서 여는 추가 팝업은 `부모화면ID-pNN` 형식을 사용한다. 예: `BAS-03-p01`. 제목 해시를 ID로 사용하지 않는다. ID는 재방문·브라우저·열기 순서와 관계없이 동일하게 유지하며, 공통 스크립트의 기존 유형 번호를 재정렬하지 않는다. 새 팝업 유형은 번호를 추가하여 등록한다.
- 화면ID와 설명 버튼은 흰색 팝업 본문 바깥 위의 검토 도구 영역에 둔다. 본문 안의 제목에는 ID나 설명 버튼을 넣지 않는다.
- 제목과 오른쪽 X 닫기 버튼을 같은 줄에서 수직 중앙 정렬한다. X에는 접근 가능한 닫기 이름을 제공하며 기존 닫기·취소 동작을 유지한다.
- 실행 버튼은 중앙 정렬하고 본 콘텐츠와 위쪽 간격을 15px로 둔다. 폼 안의 버튼은 폼 연결 및 파일·필수 입력 검증을 유지한다. 페이지 단위 버튼의 우측 최하단 규칙과 구분한다.
- 구현은 `gfair_cs/include/popup-description-example.js`와 `gfair_cs/css/popup-description-example.css`에서 관리한다. 팝업별 설명 저장은 해당 팝업 ID를 기준으로 하며 기존 페이지 설명과 구분한다. 단순 배치 변경만으로 알럿/컨펌을 새로 만들지 않는다.

저장소 이름은 `html`, 프로젝트 폴더는 `gfair_cs`를 사용한다.

- 공통 도구: `common/include/`의 로그인, Description, 번호 라벨과 댓글 기능.
- 공통 스타일: `common/css/`.
- 공통 서버 주소: `common/config.js`의 `server` 한 곳에서 관리.
- 프로젝트: `gfair_cs/` 아래 화면·데이터·업무별 스크립트·스타일.
- 공개 프로젝트 목록: 저장소 루트 `index.html`.

새 프로젝트를 추가할 때:

1. 새 프로젝트 폴더와 화면을 추가하고 `<body data-project="프로젝트ID" ...>`를 지정한다.
2. 공통 도구는 기존 프로젝트의 footer.js와 같이 `common/`에서 불러온다. 공통 스크립트를 프로젝트 안에 복제하지 않는다.
3. 공동작업 서버의 `server/projects.mjs` 등록부에 프로젝트 ID, 제목, 권한 확인 저장소, 복귀 URL을 추가한다. 임의의 외부 복귀 URL은 받지 않는다.
4. 루트 프로젝트 목록에 링크를 추가한다.

GitHub App과 저장 서버는 그대로 공유한다. 저장소를 달리하는 프로젝트를 등록한다면 기존 GitHub App을 해당 저장소에도 설치한다.

설명·번호는 프로젝트와 화면 ID를 함께 기준으로 저장한다. 기존 설명과 댓글은 `gfair_cs`에 유지한다. 다른 프로젝트의 화면 ID가 같아도 데이터가 섞이지 않는다.

공통 상단 작업자 버튼 영역에는 `번호 숨기기 / 번호 보이기` 전환 버튼을 제공한다. 화면의 설명 번호 핀만 제어하며 Description 본문·번호·데이터·저장된 핀 위치는 유지한다. 선택 상태는 프로젝트별 현재 브라우저 탭의 세션에서 유지한다. 화면검색에서는 버튼을 숨기며, Description을 닫으면 기존 정책대로 번호 핀도 표시하지 않는다. 상단 공통 도구는 화면별 Description 작성 대상에서 제외한다.

## 화면 변경 시 Description·알럿/컨펌 동시 반영

등록·작성·수정 테이블은 한 행에 항목/입력 쌍 두 개를 기본으로 배치한다. 단독 항목이나 전체 행 앞에서 짝이 없는 항목은 표 전체 너비(100%)로 표시하고, 좁은 화면에서는 한 쌍씩 표시한다. 공통 적용은 `gfair_cs/include/write-form-layout.js`와 `gfair_cs/css/write-form-layout.css`에서 관리한다. (2026-10-23 사용자 지정)

2026-10-22 사용자 지정 공통 규칙. 모든 화면과 사용구분에 적용하며, 해당 페이지에 대해 사용자가 직접 요청한 예외가 우선한다.

- 화면 수정 요청에는 관련 Description과 알럿/컨펌 정의의 동시 수정도 포함한다. 별도 요청을 기다리지 않고 같은 작업에서 반영한다.
- 항목명·배치·입력 유형·기본값·선택 옵션·필수 여부·검색 조건·검증·버튼·이동·처리 결과·노출/권한 조건이 바뀌면, 연결된 Description을 실제 화면과 일치시킨다. 관련 화면과 사용구분에 미치는 영향도 확인한다. 동일한 기능의 설명은 기존 공통 문구와 톤을 유지한다.
- 관련 알럿/컨펌은 발생 조건, 메시지, 버튼명, 확인/취소 후 동작, 오류 조건까지 함께 점검하고 달라진 정의를 수정한다. 실제 동작 코드, 공통 메시지 데이터(`gfair_cs/data/message-specs.js`), 서버에 등록된 알럿/컨펌 설명과 관련 초안 MD가 서로 어긋나지 않게 한다. 변경과 무관한 메시지는 유지하며, 단순 스타일 변경만으로 새 알럿/컨펌을 만들지 않는다.
- Description 내용이 변경된 항목은 기획비고(`planningNote`)에 `[변경사항 있음 · YYYY-MM-DD] 변경 요약`을 남긴다. 날짜는 한국 시간을 사용하고, 무엇이 어떻게 바뀌었는지 간결하게 기록한다. 알럿/컨펌 설명이 변경된 경우에도 같은 규칙을 적용한다.
- 신규 디스크립션 초안 작성·등록 자체는 위 변경 알림 대상에서 제외한다. `초안 작성`, `초안 등록` 안내를 기획비고에 넣지 않는다. 기존 설명을 실제로 변경한 경우의 변경 알림과 검토가 필요한 실질적인 기획비고는 유지한다.
- 기존 기획비고를 삭제하거나 덮어쓰지 않고 변경 안내를 추가한다. 동일 작업의 같은 안내는 중복 추가하지 않으며, 변경되지 않은 항목에는 안내를 넣지 않는다. 기존 비고와 합쳐 입력 제한을 넘으면 기존 내용을 임의로 잘라내지 않고 저장 가능한 방식으로 정리한 뒤 보존 여부를 확인한다.
- 기존 설명 ID·댓글·번호와 사용자가 조정한 핀 위치는 유지한다. 항목의 이동·추가·삭제로 연결 대상이나 번호가 달라져야 할 때만 실제 화면에 맞춰 수정한다.
- 완료 전 실제 화면, 저장된 Description, 알럿/컨펌 정의를 대조하고, 변경 안내가 기획비고의 빨간색 표시 및 공통 기획비고 팝업에서 조회되는지 확인한다. 로컬 초안만 수정한 상태를 서버 등록 완료로 보고하지 않는다.
- 화면·Description의 실제 변경은 기존 페이지별 버전·개정이력 규칙을 따른다. 이 공통 MD 규칙만 수정한 경우에는 페이지 버전과 개정이력을 올리지 않는다.

이 규칙의 “동시 반영”은 화면 수정 작업의 필수 완료 조건이다. MD 자체가 실행 중인 화면 변경을 감지하거나 서버 데이터를 자동 갱신하는 기능을 제공하는 것은 아니다.
